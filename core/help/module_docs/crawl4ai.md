# Crawl4AI

## What is Crawl4AI

Crawl4AI is the RAG-friendly web crawler in your stack. Give it a URL and it
drives a real headless browser, renders the page (JavaScript included),
strips the navigation and boilerplate, and hands back clean Markdown, the
extracted links and media, and — optionally — structured data pulled out by
a CSS/XPath schema or by an LLM. It is a **backend service** first: the
typical callers on this box are Dify workflows ("fetch this page and
summarise it"), the RAG pipelines that ingest web content into a knowledge
base, and your own scripts. A small interactive **Playground** UI ships in
the container for trying requests by hand.

## How to use it on this box

- **Playground (browser):** `https://crawl4ai.<domain>/playground` — sign in
  with razzfazz.ai single sign-on. Caddy attaches the module's API
  credential after the sign-in, so an authorised user needs no token there.
  See the known-issue section below before relying on it in the shipped 0.9.x version.
- **API from other modules:** `http://crawl4ai:11235` inside the stack
  network, with the bearer token from `CRAWL4AI_API_TOKEN`. This is what a
  Dify HTTP-Request node uses (the container name is on the
  `DIFY_DOC_TOOLS_SSRF_ALLOW` list, so the SSRF proxy lets it through).
- **API from the host:** `http://127.0.0.1:<CRAWL4AI_PORT>` (default
  `8201`), same bearer token.

The main endpoints are `POST /crawl` (one or more URLs, full result),
`POST /crawl/stream` (NDJSON, one line per URL), `POST /md` (Markdown only)
and `GET /health` (liveness, no token needed). Every request body carries a
`browser_config` and a `crawler_config`, and since 0.9.0 both must be sent in
the server's **typed** form — an object with a `type` naming the config class
and its fields under `params` — not as a bare dictionary.

## Configuration

| Key | Meaning |
|---|---|
| `CRAWL4AI_VERSION` | Pinned `unclecode/crawl4ai` image tag (default `0.9.3`) |
| `CRAWL4AI_PORT` | Host-loopback port the container's internal `:11235` is published on (default `8201`) |
| `CRAWL4AI_DOMAIN` | Public subdomain, defaults to `crawl4ai.<domain>` (Authentik forward-auth in front) |
| `CRAWL4AI_CLIENT_SECRET` | Authentik forward-auth client secret, generated by `rzfz init` |
| `CRAWL4AI_API_TOKEN` | Bearer credential of the crawl4ai API itself — required since 0.9.0, generated by init/upgrade and injected by Caddy for signed-in users |

The module is enabled by the `crawl4ai` compose profile; apply a change with
`docker compose up -d --force-recreate crawl4ai`. Outbound fetches from a
crawl go straight to the target site (the crawler is the one component that
must reach the open internet), so on an air-gapped box it can only crawl
hosts you can reach from the stack network.

## Known issue: the bundled Playground UI in 0.9.x

The Playground page shipped inside the 0.9.x image is out of step with its
own server. The symptoms, reproduced on this stack:

- `/crawl (batch)` shows a client-side error such as *"Unexpected
  non-whitespace character after JSON at position …"* — the server answers
  with multi-document NDJSON, the UI parses it as a single JSON document.
- `/crawl/stream`, `/md` and `/llm` are rejected by the server with
  *"type must be CrawlerRunConfig or BrowserConfig"* — the UI still sends
  plain config dictionaries, the server requires the typed form.

The container log shows those same runs completing successfully
(FETCH / SCRAPE / COMPLETE): the crawler and its API work, only the bundled
UI is broken. Modules that talk to the API directly (Dify document tools,
RAG pipelines) are not affected. Until an image with a matching Playground
is pinned, use the API — this request is known to work on this box:

```bash
TOKEN=$(grep '^CRAWL4AI_API_TOKEN=' ~/razzfazz-ai-service-stack/.env | cut -d= -f2-)
curl -s http://127.0.0.1:8201/crawl \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "urls": ["https://example.com"],
    "browser_config": {"type": "BrowserConfig", "params": {"headless": true}},
    "crawler_config": {"type": "CrawlerRunConfig", "params": {
      "stream": false,
      "cache_mode": {"type": "CacheMode", "params": "bypass"}
    }}
  }'
```

The reply is `{"success": true, "results": [...]}` with the page's Markdown
under `results[0].markdown`. From inside the stack replace
`127.0.0.1:8201` with `crawl4ai:11235`; for `/crawl/stream` read the answer
line by line (NDJSON). Read the token with `grep`, as above — never `source`
the `.env` file, its values contain shell metacharacters.
